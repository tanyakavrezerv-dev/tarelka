# «Тарелка» - MVP для учебной защиты

> статус: предыдущая редакция. Для реализации использовать [уточнённое ТЗ v2](tarelka-course-mvp-v2.md). Этот файл сохранён для сравнения решений.

## Цель этой версии

Сделать демонстрационный web-MVP, который показывает основной продуктовый цикл:

> выбрать меню -> увидеть КБЖУ и стоимость -> получить список покупок -> отметить покупку -> обновить кладовку

Эта версия предназначена для защиты домашнего задания. Она не должна решать все будущие задачи продукта.

## Формат размещения

Рекомендуемый вариант - статический сайт в GitHub Pages.

GitHub Pages публикует HTML, CSS и JavaScript из GitHub-репозитория и подходит для клиентского приложения без серверной части. [GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

В учебной версии:

- данные хранятся в браузере;
- сервер и регистрация не нужны;
- приложение работает на телефоне и компьютере;
- основная демонстрация проходит через один браузер;
- перенос данных выполняется через JSON-файл;
- список покупок можно скопировать текстом.

Важно: GitHub Pages делает сайт публично доступным. В репозитории нельзя хранить личные данные, реальные резервные копии или секреты. [GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## Что показываем на защите

1. открыть готовую неделю;
2. заменить или добавить блюдо;
3. увидеть изменение КБЖУ;
4. увидеть изменение стоимости;
5. открыть список покупок;
6. показать группировку по магазинам;
7. отметить товар купленным;
8. добавить его в кладовку;
9. изменить меню и показать пересчёт;
10. экспортировать данные.

## Экраны учебного MVP

### 1. Неделя

- переключение недели;
- текущий день;
- меню по приёмам пищи;
- пустые слоты;
- КБЖУ дня;
- стоимость недели;
- кнопка «Список покупок».

На компьютере можно показать сетку недели. На телефоне отображать один день с переключением.

### 2. Добавление блюда

- поиск по каталогу;
- фильтр по типу приёма пищи;
- список базовых рецептов;
- добавление блюда в слот;
- количество порций;
- быстрый выбор недавно использованных блюд.

### 3. Список покупок

- автоматический список;
- группировка по магазинам;
- группировка по категориям;
- количество;
- упаковка;
- отметка «куплено»;
- ручное добавление;
- ручное изменение количества;
- копирование списка текстом.

### 4. Кладовка

- продукт;
- количество;
- ручное добавление;
- добавление купленного;
- списание по плану;
- исправление остатка.

### 5. Настройки

- дневная планка КБЖУ ручным вводом;
- недельный бюджет;
- магазин по умолчанию;
- светлая или тёмная тема;
- экспорт и импорт.

Историю прошлых недель можно оставить отдельным экраном или простой секцией внутри раздела «Неделя».

## Что не реализуем в учебном MVP

- регистрацию;
- синхронизацию устройств;
- Telegram-бота;
- полноценный PWA offline-режим;
- автоматический расчёт нормы по возрасту и активности;
- цены по магазинам;
- онлайн-обновление цен;
- чеки;
- штрихкоды;
- фотографии блюд;
- сроки годности;
- семейный режим;
- медицинские рекомендации;
- AI.

## Данные для демонстрации

Чтобы защита была наглядной, приложение должно открываться с готовыми данными:

- одна заполненная демонстрационная неделя;
- 20 базовых рецептов;
- около 60-80 базовых продуктов;
- несколько продуктов в кладовке;
- 2-3 магазина;
- несколько постоянных покупок;
- установленная дневная планка;
- установленный недельный бюджет.

Пользователь сразу видит рабочий результат и может начать изменять его.

## Стартовый каталог рецептов

В учебном MVP достаточно 20 реальных рецептов:

- 4 завтрака;
- 6 обедов;
- 6 ужинов;
- 4 рецепта-перекуса.

Банан, орехи и кефир должны быть отдельными продуктами, а не рецептами.

Рецепты должны использовать продукты из стартового каталога, чтобы список покупок был полностью демонстрируемым.

## Правила расчёта

### КБЖУ

Поддерживаются:

- калории;
- белки;
- жиры;
- углеводы;
- клетчатка, если значение известно.

Для готового блюда:

- ингредиенты задаются в сыром виде;
- пользователь может указать вес готового блюда;
- при отсутствии веса используется приблизительный коэффициент выхода;
- порция может задаваться граммами или количеством порций.

### Стоимость

Показываются две цифры:

- «по меню»;
- «в чеке».

Для защиты основной цифрой является «в чеке», потому что она отвечает на вопрос «сколько денег нужно на покупки».

В учебной версии цена не зависит от магазина. Магазин влияет на группировку списка, но не на стоимость.

### Упаковки

Для продукта выбирается один режим:

- фиксированная упаковка;
- на вес;
- поштучно;
- свободный текст.

Пример:

- требуется 700 г курицы;
- упаковка 900 г;
- список показывает 900 г;
- кладовка получает фактически купленное количество.

## Правила кладовки

1. продукт из кладовки вычитается при расчёте списка;
2. купленная позиция по умолчанию добавляется в кладовку;
3. пользователь может отменить добавление;
4. после завершения дня приложение предлагает списать запланированное количество;
5. пользователь может изменить остаток вручную;
6. купленная позиция не удаляется при изменении меню, если она уже отмечена как купленная.

## Рекомендуемая техническая структура

Для учебной версии достаточно:

- HTML;
- CSS;
- JavaScript;
- IndexedDB или временно localStorage для небольшого прототипа;
- JSON-файлы со стартовыми данными;
- GitHub Pages.

Если MVP будет использовать фотографии, их лучше не включать в экспорт. Для защиты проще использовать изображения, поставляемые вместе с приложением, или временно оставить карточки без фотографий.

## Переход к мобильному приложению

После защиты текущую бизнес-логику можно использовать как основу для PWA:

- заменить или усилить хранение через IndexedDB;
- добавить Service Worker;
- добавить manifest;
- включить установку на домашний экран;
- протестировать iOS Safari и Android;
- добавить устойчивую работу без интернета;
- сохранить JSON-экспорт.

Главное - не связывать расчёты с конкретными элементами интерфейса. Тогда будущая мобильная версия и Telegram-бот смогут использовать общие сущности:

- рецепт;
- продукт;
- меню;
- кладовка;
- список покупок;
- покупка.

## Переход к Telegram-боту

Telegram-бот не должен напрямую зависеть от HTML-приложения.

На следующем этапе нужно вынести бизнес-логику в отдельный слой:

- расчёт КБЖУ;
- агрегация ингредиентов;
- вычитание кладовки;
- округление упаковок;
- расчёт стоимости;
- управление планом недели.

Web-интерфейс и Telegram-бот смогут использовать один набор правил.

## Критерии готовности для защиты

MVP считается готовым, если на демонстрации можно:

- открыть приложение по ссылке;
- добавить блюдо;
- изменить порции;
- увидеть пересчёт КБЖУ;
- увидеть пересчёт стоимости;
- сформировать список покупок;
- увидеть продукты по магазинам;
- отметить товар купленным;
- увидеть изменение кладовки;
- экспортировать данные;
- обновить страницу и сохранить данные в текущем браузере.

## Формулировка проекта для защиты

> «Тарелка» - web-приложение для персонального планирования питания на неделю. Пользователь выбирает блюда и продукты, получает расчёт КБЖУ и примерной стоимости, а приложение автоматически формирует список покупок с учётом кладовки и магазинов.

В дальнейшем проект может развиться в мобильное offline-приложение и Telegram-бота с общей логикой расчётов.
